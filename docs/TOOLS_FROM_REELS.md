# Quant tools surfaced by the Reels

Reviewed 2026-10-19. This is a source audit and a research plan, not a result for any trading strategy.

## What the links actually identify

The first Reel's public Instagram caption links directly to [NautilusTrader](https://github.com/nautechsystems/nautilus_trader), and its preview shows that repository. The public embed for the second Reel returns a narration-like caption describing six roles, but does not name all six repositories. The mapping below is therefore an informed match, not a recovered list from the creator. The exact audio was not independently transcribed: Instagram exposed the captions/preview but throttled direct media access.

The second caption describes a candle forecaster, a scikit-learn portfolio optimizer, a Rust event-driven backtest/live engine, multi-venue market-making bots, a crypto bot with ML retraining and Telegram controls, and a natural-language research workspace. These are different jobs. Only the forecaster could be a new source of return predictions; optimization changes risk allocation, execution software changes how a decision is simulated or routed, and an LLM workspace generates research candidates.

## What the existing evidence says about Kronos

Kronos is the most relevant candidate because it emits future OHLCV paths. The authors' [paper](https://arxiv.org/abs/2508.02739) reports 93%/87% relative RankIC gains over selected forecast baselines and evaluates an A-share top-k/drop-n long-only portfolio. Its portfolio signal averages forecast closes over a 10-day horizon after a 90-day lookback; it holds positions at least five days, limits daily turnover, and charges 0.15% per trade. The paper reports its strongest AER/IR for Kronos-large, which the upstream README marks unavailable. Its forecast experiment also includes Binance spot crypto pairs from July 2024, using OHLC prices without volume or amount. These are meaningful author-reported tests, but they do not establish MEXC perpetual returns with funding, current venue fees, or order-book impact. The README's `sample_count` controls the number of forecast paths to generate and average; a spread across repeated stochastic paths must not be called a calibrated confidence interval without coverage tests.

There is already a useful, but non-peer-reviewed, repository issue test. Its author reports Kronos-small on 182 US equities over 85 rebalance dates: RankIC +0.022, Newey-West t=1.39, and a long-short Sharpe of 0.35 after an assumed 10 bp per-side cost. The report also says its nominal 90% forecast bands covered only 58% of realized outcomes. That is a warning against using raw sample spread for position sizing, not a definitive null: the author notes low power, and the test is US equities rather than crypto ([issue #375](https://github.com/shiyu-coder/Kronos/issues/375)). A separate rolling AAPL report says Kronos-mini underperformed persistence on daily forecast errors ([issue #354](https://github.com/shiyu-coder/Kronos/issues/354)).

The checkpoint-vintage question remains open in [issue #265](https://github.com/shiyu-coder/Kronos/issues/265). One commenter reports a separate positive residual signal in recent crypto data, but the comment does not provide a reproducible harness or data artifact. Treat it as a lead to test, not confirmation.

## Fit with this project

Do not replace the lab's event engine, cost model, frozen holdouts or paper lanes with one of these platforms. The useful separation in the Reel is sound: a forecast can produce a signal, deterministic research code can size it, and a separate execution layer can simulate decisions. The advertised tool stack does not supply our missing venue history, point-in-time universe, order-book fills, or a verified edge.

The local checkout has only a small contract snapshot, not the raw candle archive needed for a repeatable Kronos backtest; PyTorch and model weights are not installed. The project's historical holdout has already been examined across earlier trials, so it cannot become a fresh one-shot holdout for this new model. No new backtest or return statistic was run for this note.

### Best next tests

1. **Kronos forecast-to-net-return test (candidate R226; not frozen).** Before scoring anything, pin the upstream commit, tokenizer and weight hashes; resolve the June-2024 checkpoint-vintage question; specify a point-in-time MEXC universe including delisted contracts; and freeze one forecast horizon and one portfolio rule. Compare forecast rank IC and probability calibration with persistence, momentum and a simple rolling local model. Then score the fixed portfolio after actual fee assumptions, measured depth, funding and delayed execution at 1x/2x/3x costs. The sampled path dispersion must pass calibration/coverage checks before it can affect sizing. Since the old holdout is spent, confirmation should use prospectively collected on-time data, with one registered decision rule and no result-driven model/horizon search.
2. **skfolio allocation comparison.** Feed it only returns from an already frozen signal. Compare one constrained risk-parity or minimum-variance allocation against equal weight and the existing volatility-target rule, using rolling covariance estimates, a turnover limit, exposure caps, and identical costs. Judge drawdown and net return together. This tests a risk overlay; it cannot validate the signal that generated the returns.
3. **Nautilus execution parity check.** Consider it only when the lab has event-level trades/book data. Replay the same timestamps and deterministic orders through both engines, then compare fills, fees, funding and portfolio state. The current 30-minute depth snapshots cannot support a queue-position or high-frequency fill comparison.
4. **Use FreqAI, Hummingbot and research agents as engineering references.** Borrow no result from their marketing pages or generated reports. Any model/strategy they suggest is another trial, with its full search count and untouched evaluation recorded here.

The next evidence-bearing action is to make the model/data artifact reproducible and freeze the Kronos protocol. Until then, “AI confidence” should be read as an uncalibrated model output, not a probability that a coin will rise.
