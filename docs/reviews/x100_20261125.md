## 1. Where a factor of a hundred can come from (the arithmetic of the work)
- Value found ≈ (decisive observations a week) × (share aimed at real rents) × (size of a rent at the owner's reach)
  × (speed from idea to proof).
- Over the last 13 cycles each factor was low:
  - **Decisive observations:** about one per two-hour cycle, done in series by one mind.
  - **Aim:** 5 of 9 cycles changed the money plan, but the ideas came from a map of about 12 rows.
  - **Rent size:** first estimates were 2-10 times optimistic (self-review 3).
  - **Speed of proof:** forward lanes take months. The balanced design cut R530's horizon by about four.
- **A factor of a hundred is not one change.** It is about 3x on each of four factors.

## 2. The levers, by factor
### Observations a week: ×5-10 (the room)
- **Haiku members run in parallel:** auditors, readers, inventors, critics, a librarian. I set the questions and
  verify.
- **The limit is verification, not generation.** Each room report must give claims with path:line, so checking one
  takes minutes.
- **Roles that work in parallel without colliding:** one file per member, read-only repo, no journals.

### Aim: ×3-5, a rules matrix of the whole industry
- **The only breakthrough came from comparing one rule (funding) across venues.** The lab has compared about seven
  rules across about fifteen venues, by hand, over a month.
- **The matrix:** venues × mechanisms (funding formula, oracle and mark, closed-market pricing, margin modes,
  liquidation and backstop, listing and delisting, settlement, fees and rebates, index rules), filled from each
  venue's own documentation.
  - Many venues publish `llms-full.txt`: trade.xyz, Lighter, Hyperliquid, Paradex, Drift, Extended, edgeX,
    Variational, Aster, dYdX.
  - Haiku readers extract one row per venue per mechanism, with the quoted rule and its URL.
  - I verify the cells that disagree.
- **Every disagreement between venues is a candidate transfer.** The matrix turns "find an idea" into "read the
  differences".
- **Refreshed monthly,** with the changelogs, because venues move transfers by changing one parameter (xyz's oracle
  constant, Drift's floor).

### Rent size: ×2-3 on realism, which avoids losses
- **A first Fermi size names the binding constraint and the decay** (now `CLAUDE.md` step 4).
- **A scoreboard of claims made to the owner,** updated every cycle. A claim's first estimate is cut by the median
  ratio the scoreboard has measured (about 3 so far) until it is verified.

### Speed of proof: ×3-10
- **Recorded data first.** The lab's recorders hold books, oracle and mark, the LLP's and HLP's positions, funding,
  and pre-IPO markets. Several answers came from data no question had used (cycles 4, 12).
- **Variance-reduced designs before frozen lanes:** balanced books, paired venues, executable prices.
- **Events that come daily instead of weekly:** RTH-only stock perps' nights, Asian closures, hourly funding
  dislocations.
- **Precommitted decisions** (as for December), so a result turns into an action the same day.

### Knowledge: ×2, step 0 in minutes
- **A Haiku librarian at the start of every cycle** answers "which rounds, data and papers touch this mechanism?"
  with paths. It replaces my memory, which lost an eleven-round class (cycle 4).
