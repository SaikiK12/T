# Funding settlement-value source check, 2026-11-03

Existing method: M461 / R388. This is source availability and schema reading,
not an archive reanalysis, a new method or a result.

The official [Get Funding Rate History documentation](https://developers.binance.com/docs/derivatives/usds-margined-futures/market-data/rest-api/Get-Funding-Rate-History)
describes `markPrice` as the value associated with the particular funding charge.
It also lists `rateType`: ordinary funding (`Regular`) and additional funding
generated by stock dividends (`Special`). Future acquisition should retain
these fields and distinguish economic components before deduplication. The
schema alone does not show whether special components contaminated any R388 event.

Read scope: this endpoint's response fields and pagination notes, obtained by
targeted extraction of the official page. Direct HTML exceeded the bounded
capture size; no full HTML identity is claimed. No other endpoint was analyzed.

A single public REST schema probe requested BTCUSDT at the already historical
2025-05-02 08:00UTC settlement with `limit=1`. The server returned **HTTP451**
from this container. The request yielded no market values; no alternative
access or outcome calculation followed. Historical response shape, field coverage and
actual data availability remain **unverified**; documentation is not held data.
The [receipt](receipt.json) preserves the URL, observation scope and failure.

The [conditional funding-notional audit](../../../lab/funding_notional.py)
therefore requires supplied settlement values, complete schedule, payment-kind
classification and eligibility. Missing inputs stay unscored. It does not
verify actual credit or a portfolio's fills/margin. Any real reanalysis needs a
separate frozen protocol and the actual contract/value/ownership evidence.
